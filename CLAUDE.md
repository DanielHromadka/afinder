# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

aFinder is a Windows XP–style file manager for macOS (primary), Windows and Linux: Electron + TypeScript + React, built with electron-vite and packaged with electron-builder. README.md (English) is the GitHub front page (download links, highlights, building); README.cs.md (Czech) is the detailed user-facing feature reference.

## Commands

```bash
npm run dev                 # electron-vite with HMR
npm run typecheck           # tsc for both projects: tsconfig.node.json (main/preload/workers/shared) and tsconfig.web.json (renderer)
npm test                    # vitest, all src/**/*.test.ts
npm run lint                # eslint, only the React hooks rules (renderer)
npx vitest run src/shared/matcher.test.ts      # single file
npx vitest run -t "part of test name"          # single test
npm run build               # bundles into out/ (main, preload, renderer)
npm run dist                # macOS .dmg arm64 + x64 into dist/ (dist:win, dist:linux for the others)
```

Electron smoke tests run the built app (`out/`) in a real Electron with a temporary userData directory:

```bash
npm run test:automations
npm run test:activity       # AFINDER_MODEL_CACHE=<dir with downloaded e5 model> adds the real offline ONNX check
npm run test:file-assistant # requires AFINDER_LAYA_CACHE=<dir with the downloaded Laya model>
npm run test:companion      # needs `npm install` in mobile/relay: local relay + aFinder + phone client end to end, control with a stand-in helper, aFinder paired with itself
npm run test:feedback       # needs `npm install` in feedback/: local Worker + fake GitHub API + aFinder
npm run test:tools          # Tools area: calculator, worker jobs, image conversion, regex, clipboard history
npm run test:tour           # guided tour: first-start offer, Help menu, every step's target, F1 and Esc
npm run test:doom           # needs doom/build.sh first: download (checksum refusal + real), engine in its frame, keys, pause, delete
npm run test:docker         # Docker area against a fake Engine API on a unix socket (AFINDER_DOCKER_HOST)
```

`AFINDER_APP_ROOT` points a smoke test at another app root, e.g. `dist/mac-arm64/aFinder.app/Contents/Resources/app.asar`, to test the packaged build (run it with the dev `npx electron`, since the packaged binary ignores script arguments).

`typecheck` (strict, `noUnusedLocals/Parameters`) is the main gate; `lint` adds only the React hooks rules (rules-of-hooks is an error, exhaustive-deps a warning, since many effects deliberately run once or read refs). `.github/workflows/ci.yml` runs typecheck, lint and tests, the `feedback/` and `mobile/` packages, and the tools, docker, workspace and tour smoke tests under xvfb for every push and pull request.

## Architecture

**Processes.** `src/main` is the Electron main process; `src/preload` exposes a typed `window.api` through `contextBridge`; `src/renderer` is the React UI, running with `contextIsolation`, `sandbox` and no `nodeIntegration`. All file access goes through IPC, and main validates paths (`validatePath` in `fileSystem.ts`). Long-running work stays off the main thread:
- `src/workers/` hold the `utilityProcess` workers: `sizeWorker` (recursive folder sizes) and `searchWorker` (recursive search). They exit after 30 s idle and are re-forked on demand. One SizeService per window; one SearchService for the app.
- The ML workers are `worker_threads` built as extra main entries in `electron.vite.config.ts`: `activityEmbeddingWorker` (e5 embeddings) and `fileAssistantWorker` (Laya). Both use `onnxruntime-node` + `@huggingface/tokenizers` directly, download pinned model revisions only on explicit user request, run offline, and stop after 60 s idle.
- Automation scripts run in separate `utilityProcess` children (`automationExecutor.ts`).

**IPC contract.** Channel names are the `IPC` const in `src/shared/ipcChannels.ts`; the renderer's API is `AfinderApi` in `src/shared/types.ts`, with the domain types in `src/shared/model/` (re-exported from `@shared/types`). `src/shared/ipcContract.ts` maps each request channel to the `AfinderApi` method it serves, and both the preload's `call()` and main's `handle()` are typed from it, so a handler that takes or returns something else than the API promises is a type error. Adding a call means: the `IPC` entry, the `AfinderApi` method, its line in `IpcContract`, a `handle(IPC.x, …)` in `src/main/ipc.ts` and the preload wrapper in `src/preload/index.ts`. Handlers still validate their arguments (they cross a process boundary). `handle()` wraps results as `Result<T>` (`{ok, value} | {ok:false, error}`) and turns errno codes into readable messages; the preload `call()` unwraps it and throws on error. File-changing handlers are wrapped in `audit.track(...)` so they show up in the activity history.

**Virtual file system.** `src/main/services/vfs.ts` is the only place that knows whether a path is local, inside an archive (read-only, extracted lazily to a temp dir), on a remote connection, or the remote mounts folder. Services call `vfs.locate` / `realPath` / `assertWritable` / `isVirtual` instead of checking kinds themselves. Watching, folder sizes, recursive search, git and shells only work on local paths. Remote backends (SFTP, S3, SharePoint/OneDrive via Graph) implement `RemoteProvider` in `services/remote/provider.ts`, are mounted under `<userData>/Remote/<id>`, and are imported lazily.

**Settings** are persisted by `services/settings.ts` (`loadState`/`updateState`, sanitized) through `services/jsonStore.ts`, which writes a temporary file and renames it and moves an unparsable file aside (`settings.json.corrupt-…`) instead of overwriting it; automations use the same store. `updateState` returns the save error, and a failed save from the renderer is reported once (`app/useSettingsSync.ts`). Changes are broadcast so that every open window applies them immediately.

**Renderer structure.** `App.tsx` composes hooks in `src/renderer/src/app/`: `paneModel.ts` (pure, tested transitions of panes and tabs), `useSettingsSync`, `useWorkspaceLayout` (workspaces, areas and their menus), `useConsoleSessions`, `windowCommands` (palette) and `useAppKeyboard`. `TabView.tsx` composes `components/tab/`: `useDirectoryNavigation` (listing, history, navigate/refresh behind `lib/loadGate.ts`, so late answers never win), `useFileSelection`, `useTransferFlow` (plans, conflicts, progress, file clipboard), `useFolderSizes`, `useRecursiveSearch`, `useGitStatus`; its context menu, palette commands and keyboard are built from one `TabContext` (`tab/actions.ts`). Rows are built by the pure `lib/fileRows.ts`. Dialogs use `components/Dialog.tsx`: `<Dialog>` over a backdrop or `useModalDialog` for native `<dialog>`s, both with `DialogTitleBar`, Escape, first focus and focus return; `lib/modal.ts` says whether something modal has the keyboard.

**Keep the main process lean.** Heavy dependencies (Office parsers, MCP SDK + zod, electron-updater, remote SDKs) are loaded with `await import()` at first use, not at module top level. Follow this pattern for any new heavy dependency used in main.

**Packaging.** `electron-builder.yml` unpacks native modules (`node-pty`, `onnxruntime-node`) from the asar. `scripts/after-pack.cjs` deletes ONNX Runtime binaries for other platforms/architectures and the duplicate macOS dylib. `electronLanguages` keeps only en/cs/de/es. `node-pty` for Linux must be built on Linux (CI builds x64 natively and cross-compiles arm64); `cpu-features` is overridden with an empty package (`scripts/no-cpu-features`) because it does not build against Electron 44 there. Releases are cut by `release.yml` and published to `DanielHromadka/afinder-downloads`: every push to main builds, signs, notarizes and publishes the macOS version plus Linux AppImage, deb and rpm for x64 and arm64 (the Windows installer and `latest.yml` are copied over from the previous release); a manual run (`workflow_dispatch`) also builds Windows and can raise the minor or major version. Updates use electron-updater everywhere (`services/updater.ts`): it asks first, then downloads, installs and restarts. macOS installs the signed `aFinder-<arch>-mac.zip` through Squirrel.Mac (the .dmg is only for first installs and the fallback), so the release must stay signed and notarized and must upload the zips with `latest-mac.yml`.

**Phone companion** (`services/companion.ts`, off by default, imported lazily): an outgoing WebSocket to the Cloudflare relay in `mobile/relay`, pairing by QR code + SAS, and an end-to-end encrypted RPC for the Expo app in `mobile/app`. Protocol and crypto live in `src/shared/companion/` and are shared with the relay and the app; they must stay free of Node, DOM and React Native APIs. `mobile/` has its own packages, tests and README.

**Computer ↔ computer and remote desktop.** Another aFinder is a remote connection of type `afinder` (`services/remote/afinder.ts`), paired with the companion's pairing link and talking through the shared client. Paired devices have a `kind` (sent in the pairing message; old phone apps send none, so `phone`): phones live in Settings → Phone (`companionEnabled`), computers in Settings → Remote access (`computersEnabled`), with separate switches, pairing and lists over one relay connection, and only computers may get control. The shared client is `src/shared/companion/client.ts` (also used by the phone app). `services/remoteDesktop.ts` opens `remote.html` (`renderer/src/remote`), which does the WebRTC itself and sends mouse and keyboard on the `input` data channel; signalling goes through the encrypted session. On the controlled side the hidden capture page forwards that channel to `services/inputInjector.ts`, which validates and maps events (`src/shared/companion/input.ts`) and writes them to the Rust helper `native/afinder-input` (enigo). Screen and control sessions are not confirmed on the controlled computer (the per-device permission is the consent); the banner shows them. Build the helper with `npm run build:input` (`--host` for this machine only); `scripts/after-pack.cjs` copies it into `resources/bin` (not for MAS, where control is off). The smoke test sets `AFINDER_INPUT_HELPER` (a stand-in helper) and `AFINDER_ICE_LOCAL` (no STUN: on one Mac, STUN makes WebRTC pick a path macOS blocks).

**Guided tour** (`components/Tour.tsx`): steps point at elements by selector, mostly `data-tour` attributes (the toolbar's `ToolButton tour=…`); keep those attributes when moving UI, and `npm run test:tour` fails if a step loses its target. Texts are `tour.<step>.title/text` with shortcuts passed as params.

**Tools area** (`components/tools/`, `services/tools.ts`, `workers/toolsWorker.ts`): every tool is a lazily loaded component; checksums, duplicates and the disk map run in a utilityProcess worker with progress and cancel; pure logic (calculator parser, units, CNB rates, treemap, encodings, passwords, colours) lives in `src/shared/tools/` with tests. Tool inputs persist in localStorage (`afinder.tools.*`); the clipboard history is a setting, off by default and kept in memory only. The Task Manager (`tools/SystemMonitor.tsx`, `services/systemMonitor.ts`) reads through `systeminformation` in its own utilityProcess (`workers/systemWorker.ts`), polled only while visible; fans come from Linux hwmon only. It is also an area of its own (editor `monitor`, the same component).

**Docker** (`services/docker.ts`, `components/docker/`, `src/shared/docker.ts`): an area (editor `docker`) talking to the Docker Engine API over its local socket or named pipe with plain `http` (no client library), imported lazily. `DOCKER_HOST` wins, else the usual sockets are pinged in order; `AFINDER_DOCKER_HOST` overrides both for the smoke test. Logs, stats, pulls and engine events are streams with ids (`docker:stream` events, stopped from the renderer or when the window goes); lists reload on engine events, live usage polls only while visible. Compose has no engine API: its commands run the docker CLI with an argument array from the project's labels (working dir, config files); the container shell is `docker exec` typed into a console session (`terminals.run`), built from a validated id. Pure parts (log frame demux, stats arithmetic, grouping, reference checks) live in `src/shared/docker.ts` with tests. The process table in the Task Manager and the Docker lists reuse the file list's classes (`list-header`, `col-header`, `row`, `cell`), so themes style them with the file list.

**Release notes** (`src/shared/releaseNotes.ts`, `scripts/release-notes.mjs`, `services/releaseNotes.ts`, `ReleaseNotesDialog`): the release workflow builds them from the commits since the commit marker in the last release's body (`Release-Note: <text>` in a commit message replaces its subject, `Release-Note: none` hides it; mobile/website/docs/feedback commits are left out), uses them as the GitHub release body and writes `build/release-notes.json` (`[]` in the repository), packaged as an extra resource for the in-app "What's new" dialog, which opens once after an update. The update prompt shows the new version's notes from electron-updater.

**Doom** (`components/games/DoomGame.tsx`, `services/doom.ts`, `src/renderer/src/doom/`, `doom/`): nothing of Doom ships with aFinder. `doom/build.sh` (Docker, wasi-sdk) builds doomgeneric (GPLv2) as a WASI reactor `doom.wasm` and puts it with Freedoom (BSD) and the GPL source tarball into `doom/out/`, which is uploaded to the `doom-<n>` release of `afinder-downloads`; `src/shared/doom.ts` pins the files by size and SHA-256. Main downloads them only from the Download button into `<userData>/Games/doom`. The game runs in `doom.html`, an iframe whose CSP alone allows `'wasm-unsafe-eval'`; the panel passes it the bytes, and the module sees only the in-memory WASI shim (`doom/wasi.ts`). Doom busy-waits on its clock, so the host sets the time per tic and the shim lets such loops end; never hand it a real clock.

**Feedback** (`services/feedback.ts`, `FeedbackDialog`): the toolbar button shoots the window (`capturePage`, JPEG ≤1600 px) before the modal opens; main validates with `src/shared/feedback.ts` and posts to the Worker in `feedback/`, which files a GitHub issue in a private repo. Sent only from the Send button.

**MCP server** (`services/mcpServer.ts`): Streamable HTTP on 127.0.0.1 only, bearer token, rejects browser origins and foreign Host headers, off by default. A fresh `McpServer` is built per request, and write tools are registered only while settings allow them.

## Conventions

- **i18n:** `src/shared/i18n/cs.ts` is the reference dictionary. en/de/es must contain every key with matching `{params}`; typecheck and `i18n.test.ts` enforce this. Key suffixes `.mac/.win/.linux` are per-platform variants (`tos()`), and `.one/.few/.many/.other` are plural forms (`plural()`). User-facing strings always go through `t()`.
- **Themes:** add an entry to `THEMES` in `src/shared/model/settings.ts`, create `src/renderer/src/styles/theme-<id>.css` scoped under `:root[data-theme='<id>']` (override CSS variables first), then import it in `src/renderer/src/main.tsx`. Base styles and tokens are in `styles/xp.css`; each feature's styles are in `styles/features/*.css`, imported right after it in `main.tsx` in a fixed order (rules of equal weight later in the list win). The Apple theme uses the system's window buttons (macOS traffic lights in its own title bar, `titleBarOverlay` on Windows/Linux); the others draw their own. Windows/Linux can add the overlay only when a window opens, so switching to or from that theme replaces each window (`replaceWindow` in `main/index.ts`): the page hands over its tabs, console sessions (still running, `terminals.handover`) and maximized area as a `WindowHandover`.
- **Shortcuts:** on Windows/Linux, avoid Ctrl+Alt combinations (AltGr on European layouts); Ctrl+Alt+T is the one exception. Paths must work for POSIX and Windows (`src/shared/paths.ts`, usable from the renderer).
- **Renames and overwrites:** decide whether a target is the same item by identity (`services/fileIdentity.ts`: device and inode, or the canonical path), never by comparing path text; case-sensitive disks exist on every platform.
- **External processes:** spawn with an argument array, never through a shell string.
- **Privacy defaults:** AI and ML features (activity history, semantic search, file assistant, MCP) are off by default, and models download only from an explicit button. Keep that behaviour.
- **Code style:** compact code with short doc comments explaining *why*. Match the surrounding file. In stateful and async logic (services, effects, cleanup after errors) put one statement per line, so side effects and cleanup stay easy to follow.
